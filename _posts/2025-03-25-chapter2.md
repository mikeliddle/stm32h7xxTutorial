Let's take what we learned in Chapter 1 and expand it with GPIO. GPIO stands for General Purpose Input/Output, and is a common way to interface with the outside world in embedded systems. In this chapter, we will learn how to configure GPIO pins for input and output, and how to read and write to them.

## Blinky and the HAL

Let's take a look at the blinky example from Chapter 1 and talk through the code a bit deeper.

```c
int main(void) {
    // Initialize the Hardware Abstraction Layer (HAL) so we can use it.
    // This is provided as part of our STM32 libraries we are including in main.h
    HAL_Init();
    // Initialize GPIO
    MX_GPIO_Init();

    while (1) {
        // The program will run indefinitely, blinking the LED on and off.
        HAL_GPIO_TogglePin(GPIOE, GPIO_PIN_3); // Toggle the LED pin
        HAL_Delay(1000); // Delay for 1000 milliseconds
    }

    // We won't get here because of the while loop above.
    return 0;
}
```

First, we initialize the HAL, then the GPIO settings. Let's take a look at those functions:

```c
static void MX_GPIO_Init(void) {
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    // Enable GPIO clock for the GPIO bank we are using (GPIOE)
    __HAL_RCC_GPIOE_CLK_ENABLE();

    // Configure GPIO pin for LED
    // Set the LED pin to low to start
    HAL_GPIO_WritePin(GPIOE, GPIO_PIN_3, GPIO_PIN_RESET);
    // Pin 3 for the bank
    GPIO_InitStruct.Pin = GPIO_PIN_3;
    // Push-pull output mode, we are using this pin for output
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
    // No pull-up or pull-down resistors, this will be useful for input.
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    // Low speed since we are just using this to blink an LED.
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
    // Initialize the GPIO pin in Bank E
    HAL_GPIO_Init(GPIOE, &GPIO_InitStruct);

    // If you had more pins to initialize, that would happen here.
}
```

`__HAL_RCC_GPIOE_CLK_ENABLE()` is a macro that enables the clock for the GPIO bank we are using. This is necessary to use the GPIO pins in that bank. TODO: update this with more clarity

In general with GPIO, there are two operations: read and write. For some boards, these are further separated into digital read/write and analog read/write. In this case (LED blink) we are using a digital output, meaning we care about high vs low. In voltage terms this is either 3.3v or 5v for high, and around 0v for low. The HAL is abstracting that away from us with `GPIO_PIN_RESET` and `GPIO_PIN_SET`. In this case, `HAL_GPIO_WritePin(GPIOE, GPIO_PIN_3, GPIO_PIN_RESET)` sets the pin to low to start. In terms of Output, this is an "off".

This is generally good practice for both input and output as it defines our default state. If we are going to be processing events based on pin state, it is good to have a known start state.

## Pin Modes

Looking at the `stm32h7xx_hal_gpio.h` file, we can see the different modes we can set for GPIO pins. The HAL provides a set of macros to define the mode of the pin.

```c
#define GPIO_MODE_INPUT                 MODE_INPUT                                                  /*!< Input Floating Mode                                                */
#define GPIO_MODE_OUTPUT_PP             (MODE_OUTPUT | OUTPUT_PP)                                   /*!< Output Push Pull Mode                                              */
#define GPIO_MODE_OUTPUT_OD             (MODE_OUTPUT | OUTPUT_OD)                                   /*!< Output Open Drain Mode                                             */
#define GPIO_MODE_AF_PP                 (MODE_AF | OUTPUT_PP)                                       /*!< Alternate Function Push Pull Mode                                  */
#define GPIO_MODE_AF_OD                 (MODE_AF | OUTPUT_OD)                                       /*!< Alternate Function Open Drain Mode                                 */
#define GPIO_MODE_ANALOG                MODE_ANALOG                                                 /*!< Analog Mode                                                        */
#define GPIO_MODE_IT_RISING             (MODE_INPUT | EXTI_IT | TRIGGER_RISING)                     /*!< External Interrupt Mode with Rising edge trigger detection         */
#define GPIO_MODE_IT_FALLING            (MODE_INPUT | EXTI_IT | TRIGGER_FALLING)                    /*!< External Interrupt Mode with Falling edge trigger detection        */
#define GPIO_MODE_IT_RISING_FALLING     (MODE_INPUT | EXTI_IT | TRIGGER_RISING | TRIGGER_FALLING)   /*!< External Interrupt Mode with Rising/Falling edge trigger detection */

#define GPIO_MODE_EVT_RISING            (MODE_INPUT | EXTI_EVT | TRIGGER_RISING)                    /*!< External Event Mode with Rising edge trigger detection             */
#define GPIO_MODE_EVT_FALLING           (MODE_INPUT | EXTI_EVT | TRIGGER_FALLING)                   /*!< External Event Mode with Falling edge trigger detection            */
#define GPIO_MODE_EVT_RISING_FALLING    (MODE_INPUT | EXTI_EVT | TRIGGER_RISING | TRIGGER_FALLING)  /*!< External Event Mode with Rising/Falling edge trigger detection     */
```

First we have our "Digital Input" mode. This is for devices like buttons and switches where we are identifying a high or low state.

Next we have our "Digital Output" modes. This is for devices like LEDs and relays where we are controlling a high or low state. These are further broken down into Push-Pull and Open Drain. Push-Pull uses transistors to drive the pin high or low, while Open drain uses a transistor to pull the pin low, and a resisistor to pull high.

The next two modes are Alternate Function modes. These are used for applications where you need to use the pin for a different function, such as UART, I2C, SPI, etc. The two modes are Push-Pull and Open Drain.

The next mode is Analog mode. This is used for applications where you need to use the pin for analog input or output, such as ADC or DAC. This is what you'd typically use for potentiometers and other analog sensors as well.

## Banks vs Pins

If you've programmed an Arduino before, this may be new to you, but the STM32H7 splits the GPIO pins into banks, with pin numbers for each bank. On the STM32H7, there are 16 GPIO pins, with the banks being A-E. The pin numbers are 0-15, so the first pin in bank A is A0, and the last pin in bank E is E15. This is important to remember when configuring GPIO pins, as you will need to specify both the bank and the pin number. We will use this to our advantage later, but this is why we are using `GPIOE` in the example above. The LED is connected to pin 3 of bank E, so we need to specify that when configuring the GPIO pin.
